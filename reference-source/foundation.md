# Canvas 정원 레퍼런스 보드

확인일: **2026-10-17 UTC**. 아래 공개 원문 4개를 실제 조회했다. 저자가 공개한 교재, MDN 공식 문서, W3C WAI 문서를 사용했다.

이 보드는 구현 원리를 비교하기 위한 기록이다. 타인의 코드·이미지·페이지 구성을 복사하지 않는다. ‘피할 특징’과 ‘적용’은 원문에 대한 프로젝트의 판단이며, 원문이 해당 구현을 요구한다는 뜻은 아니다. 적용 위치는 구현을 위한 파일·역할 매핑이다.

## 1. The Nature of Code — Fractals

- **출처:** Daniel Shiffman, [Chapter 8: Fractals](https://natureofcode.com/fractals/), 특히 Recursion, Trees, The Stochastic Version.
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 작은 가지에 같은 규칙을 반복하는 재귀 구조와 종료 조건을 설명한다. 각도·길이·분기 수의 무작위 변화는 나무 형태에 다양성을 주며, 지나치게 넓은 변화 범위는 자연스러움을 떨어뜨릴 수 있다고 설명한다.
- **배울 특징:** 큰 줄기에서 작은 가지로 이어지는 계층, 길이와 굵기의 점진적 감소, 제한된 불규칙성으로 생기는 서로 다른 실루엣.
- **피할 특징:** 완벽한 좌우 대칭, 무제한 분기, 매 프레임 새로운 난수를 뽑아 생기는 형태의 떨림. 교재 예제의 p5.js 코드나 이미지를 가져오는 방식도 피한다.
- **이 프로젝트 적용 위치:** `engine.js`의 가지 데이터 생성. 프로젝트 고유의 시드 난수와 깊이·최소 길이·총 가지 수 상한을 사용한다. `garden.js`는 생성된 구조를 성장 진행도에 따라 그린다. 시드 재현성과 상한은 이 프로젝트의 설계 선택이다.

## 2. MDN — Basic usage of canvas

- **출처:** [Basic usage of canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Basic_usage).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** Canvas의 실제 그리기 크기와 CSS 표시 크기는 다르며, 비율이 어긋나면 그림이 왜곡된다. 2D context 획득, 지원 여부 확인, Canvas 내부의 대체 콘텐츠를 설명한다.
- **배울 특징:** 그리기 표면을 명시적으로 초기화하고, 그림을 읽기 어려운 경우에도 의미 있는 텍스트를 제공하는 구조.
- **피할 특징:** CSS로만 크기를 늘려 흐릿하거나 늘어난 정원, 그림 속에만 존재하는 필수 안내와 조작 버튼, Canvas 초기화 실패 시 빈 화면.
- **이 프로젝트 적용 위치:** `garden.js`의 Canvas 초기화·리사이즈 처리, `index.html`의 정원 설명·상태 텍스트·HTML 버튼, `styles.css`의 화면 비율 관리. 고해상도 배율 처리는 별도 프로젝트 설계로 적용하고 표시 좌표와 그리기 좌표를 일치시킨다.

## 3. MDN — requestAnimationFrame()

- **출처:** [Window: requestAnimationFrame() method](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 콜백 요청은 한 번만 실행되므로 다음 프레임이 필요하면 다시 요청한다. 콜백의 시간값으로 진행량을 계산해야 높은 주사율 화면에서도 속도가 빨라지지 않는다. 반환된 요청 ID는 취소에 사용한다.
- **배울 특징:** 화면 갱신에 맞춘 단일 애니메이션 루프, 시간 기반 진행도, 끝나는 시점이 명확한 성장.
- **피할 특징:** 프레임마다 고정량을 더하는 성장 속도, 재생 버튼을 누를 때마다 중첩되는 루프, 완료·일시정지 뒤에도 계속되는 불필요한 요청.
- **이 프로젝트 적용 위치:** `garden.js`의 성장·재생·일시정지 루프. 하나의 요청 ID와 명시적 실행 상태를 관리하고 시간 차이로 진행도를 계산한다. 재개 때 시간 기준을 갱신하는 것은 정원이 갑자기 완성되는 현상을 피하기 위한 프로젝트 선택이다.

## 4. W3C WAI — C39, prefers-reduced-motion

- **출처:** [C39: Using the CSS prefers-reduced-motion query to prevent motion](https://www.w3.org/WAI/WCAG22/Techniques/css/C39).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 사용자의 시스템 동작 줄이기 설정에 맞춰 CSS 애니메이션을 억제하는 방법을 제시한다. 정적 스타일을 기본으로 두고 선호 설정이 없을 때 동작을 켜는 방식도 설명한다. C39는 WCAG를 만족시키는 방법의 예시이며, 그 자체가 필수 규칙은 아니다.
- **배울 특징:** 동작을 줄여도 정보와 조작 목적을 유지하고, 실제 설정을 켠 상태에서 움직임이 억제되는지 확인하는 검증 방식.
- **피할 특징:** 성장 효과·장식 흔들림의 강제 재생, 동작을 껐을 때 사라지는 결과, CSS 미디어 쿼리만 추가하고 JavaScript Canvas 루프도 자동으로 멈췄다고 가정하는 구현.
- **이 프로젝트 적용 위치:** `styles.css`의 장식 전환, `garden.js`의 동작 선호 감지와 성장 표시, `index.html`의 재생·일시정지 안내. C39의 직접 범위는 CSS다. Canvas에 같은 선호를 반영해 완성 장면을 정적으로 보여주는 것은 이 프로젝트의 확장 적용이다.
