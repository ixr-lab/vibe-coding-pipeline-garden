# 실제 수정·발전 비교

평가 기준은 requirements.md에서 먼저 고정했다. 점수나 사용자 선호를 추측해 수치화하지 않는다. 아래 시각 관찰은 AI의 판단이다.

## v0 — 실행 가능한 최소 기능
실행: evidence/v0-run.json. 원본 화면: v0-desktop.png / v0-mobile.png / v0-canvas.png.
통과한 자동 시험: 결정론/형상 2개, 클릭·정지 버튼 상태·초기화·PNG·가로 넘침 smoke.
부족점: 원형 잎과 비등방 배율 때문에 도식처럼 보임, 우측 수관 잘림, 키보드 심기/모션 감소 미구현. 이는 실제 화면과 코드를 보고 기록했다.

## 실험 1 — v0→v1 (실행 전 가설)
- 의도: 살아 있는 식물로 읽히는 형태와 정돈된 풍경.
- 원인 가설: x/w와 y/h의 다른 배율이 가지를 눕힌다. 원형 끝점은 잎 방향을 전달하지 않는다.
- 변경 예정: 동일 축 배율, 곡선 가지, 방향성 있는 잎, 제한된 잎색, 층진 지면, 미세한 직접 생성 질감.
- 회귀 확인 예정: 같은 seed 데이터, 클릭/정지/초기화/PNG/모바일 overflow, 동일 고정 조건 PNG.
- 실제 실행·관찰·채택 판정: 아직 대기. 아래 후속 기록으로만 추가한다.

### 실험 1 실제 결과 — 2026-10-17T01:55:17Z
같은 viewport/seed/frame/wind/density로 v1-desktop.png와 v1-mobile.png 생성. AI가 두 원본을 직접 열어 v0와 비교했다. 줄기가 세로로 서고 잎의 방향·색차가 구분되며 오른쪽 수관이 화면 안에 들어왔다. 그림 영역은 제어 패널 높이를 채우도록 변경되어 Canvas 자체 높이는 v0 550px에서 v1 630px이 됐다. 비교 viewport는 동일하며, 화면 구성 개선도 실험 변수다. 식물의 형태 변화만 엄밀히 분리한 실험은 아니므로 효과를 개별 항목에 수치 배분하지 않는다.

클릭 5→6, 초기화 0, 정지 버튼 상태 true, PNG 234,450bytes, 예외 0, mobile overflow false로 기존 smoke 회귀 없음. 추가 layout 시험 첫 구현 후 실행은 2/3: 119.70000000000005와 119.7의 부동소수점 완전일치 단정 때문에 실패했다(evidence/engine-v1-initial.txt). 구현 결함이 아닌 검증 오차임을 로그로 확인하고 허용오차 1e-9로 수정한다. 실패를 삭제하거나 통과로 세지 않는다.

**판정: 채택(AI 시각 판단).** 사용자 미적 만족: 확인 대기. 남은 실제 부족점: mobile의 정지/저장 버튼까지 스크롤이 길다. 키보드로 정원에 focus 후 Enter를 눌러도 심기 이벤트가 없다. 시스템 동작 줄이기를 읽지 않고 RAF는 정지/고정 화면에서도 계속 예약한다(코드 점검, 다음 audit로 실제 확인 예정).

## 실험 2 — v1→v2 (실행 전 가설, 2026-10-17T01:56Z)
- 의도: 보기 좋은 그림을 모바일/키보드로 편하게 조작하고, 동작 줄이기·정지 의도를 실제 실행에 반영.
- 원인 가설: 포인터 전용 이벤트와 연속 RAF 루프, 세로형 제어 배치가 접근성과 정지 상태 비용을 만든다.
- 변경 예정: 방향키로 심기 위치 이동 + Enter/Space 심기 + 대체 심기 버튼, 시스템/수동 동작 줄이기, 이벤트 기반 RAF 시작/취소, 배경 캐시, 모바일 제어 2열과 주요 버튼 상단 배치.
- 고정 비교 조건은 유지. 재현 URL은 고정 상태임을 UI에 명시. 모션 감소는 즉시 완성된 식물과 흔들림 없는 화면을 제공.
- 검증 예정: 실제 키보드 심기, pause 전후 픽셀/RAF, reduced-motion RAF, mobile 버튼 크기, 32개 상한, seed/density/wind 재현, PNG와 canvas 일치.
