# Canvas 정원 레퍼런스 보드

확인일: **2026-10-17 UTC**. 아래 공개 원문 4개를 실제 조회했다. 저자가 공개한 교재, MDN 공식 문서, W3C WAI 문서를 사용했다.

이 보드는 구현 원리를 비교하기 위한 기록이다. 타인의 코드·이미지·페이지 구성을 복사하지 않는다. ‘피할 특징’과 ‘적용’은 원문에 대한 프로젝트의 판단이며, 원문이 해당 구현을 요구한다는 뜻은 아니다. 적용 위치는 구현을 위한 파일·역할 매핑이다.

## 1. The Nature of Code — Fractals

- **출처:** Daniel Shiffman, [Chapter 8: Fractals](https://natureofcode.com/fractals/), 특히 Recursion, Trees, The Stochastic Version.
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 작은 가지에 같은 규칙을 반복하는 재귀 구조와 종료 조건을 설명한다. 각도·길이·분기 수의 무작위 변화는 나무 형태에 다양성을 주며, 지나치게 넓은 변화 범위는 자연스러움을 떨어뜨릴 수 있다고 설명한다.
- **배울 특징:** 큰 줄기에서 작은 가지로 이어지는 계층, 길이와 굵기의 점진적 감소, 제한된 불규칙성으로 생기는 서로 다른 실루엣.
- **피할 특징:** 완벽한 좌우 대칭, 무제한 분기, 매 프레임 새로운 난수를 뽑아 생기는 형태의 떨림. 교재 예제의 p5.js 코드나 이미지를 가져오는 방식도 피한다.
- **이 프로젝트 적용 위치:** `engine.js`의 가지 데이터 생성. 프로젝트 고유의 시드 난수와 깊이·최소 길이·총 가지 수 상한을 사용한다. `garden.js`는 생성된 구조를 성장 진행도에 따라 그린다. 시드 재현성과 상한은 이 프로젝트의 설계 선택이다.

## 2. MDN — Basic usage of canvas

- **출처:** [Basic usage of canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Basic_usage).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** Canvas의 실제 그리기 크기와 CSS 표시 크기는 다르며, 비율이 어긋나면 그림이 왜곡된다. 2D context 획득, 지원 여부 확인, Canvas 내부의 대체 콘텐츠를 설명한다.
- **배울 특징:** 그리기 표면을 명시적으로 초기화하고, 그림을 읽기 어려운 경우에도 의미 있는 텍스트를 제공하는 구조.
- **피할 특징:** CSS로만 크기를 늘려 흐릿하거나 늘어난 정원, 그림 속에만 존재하는 필수 안내와 조작 버튼, Canvas 초기화 실패 시 빈 화면.
- **이 프로젝트 적용 위치:** `garden.js`의 Canvas 초기화·리사이즈 처리, `index.html`의 정원 설명·상태 텍스트·HTML 버튼, `styles.css`의 화면 비율 관리. 고해상도 배율 처리는 별도 프로젝트 설계로 적용하고 표시 좌표와 그리기 좌표를 일치시킨다.

## 3. MDN — requestAnimationFrame()

- **출처:** [Window: requestAnimationFrame() method](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 콜백 요청은 한 번만 실행되므로 다음 프레임이 필요하면 다시 요청한다. 콜백의 시간값으로 진행량을 계산해야 높은 주사율 화면에서도 속도가 빨라지지 않는다. 반환된 요청 ID는 취소에 사용한다.
- **배울 특징:** 화면 갱신에 맞춘 단일 애니메이션 루프, 시간 기반 진행도, 끝나는 시점이 명확한 성장.
- **피할 특징:** 프레임마다 고정량을 더하는 성장 속도, 재생 버튼을 누를 때마다 중첩되는 루프, 완료·일시정지 뒤에도 계속되는 불필요한 요청.
- **이 프로젝트 적용 위치:** `garden.js`의 성장·재생·일시정지 루프. 하나의 요청 ID와 명시적 실행 상태를 관리하고 시간 차이로 진행도를 계산한다. 재개 때 시간 기준을 갱신하는 것은 정원이 갑자기 완성되는 현상을 피하기 위한 프로젝트 선택이다.

## 4. W3C WAI — C39, prefers-reduced-motion

- **출처:** [C39: Using the CSS prefers-reduced-motion query to prevent motion](https://www.w3.org/WAI/WCAG22/Techniques/css/C39).
- **확인일:** 2026-10-17 UTC.
- **원문에서 확인한 특징:** 사용자의 시스템 동작 줄이기 설정에 맞춰 CSS 애니메이션을 억제하는 방법을 제시한다. 정적 스타일을 기본으로 두고 선호 설정이 없을 때 동작을 켜는 방식도 설명한다. C39는 WCAG를 만족시키는 방법의 예시이며, 그 자체가 필수 규칙은 아니다.
- **배울 특징:** 동작을 줄여도 정보와 조작 목적을 유지하고, 실제 설정을 켠 상태에서 움직임이 억제되는지 확인하는 검증 방식.
- **피할 특징:** 성장 효과·장식 흔들림의 강제 재생, 동작을 껐을 때 사라지는 결과, CSS 미디어 쿼리만 추가하고 JavaScript Canvas 루프도 자동으로 멈췄다고 가정하는 구현.
- **이 프로젝트 적용 위치:** `styles.css`의 장식 전환, `garden.js`의 동작 선호 감지와 성장 표시, `index.html`의 재생·일시정지 안내. C39의 직접 범위는 CSS다. Canvas에 같은 선호를 반영해 완성 장면을 정적으로 보여주는 것은 이 프로젝트의 확장 적용이다.

# 새 수묵·담채 목표와 기존 꽃·브러시·꽃잎 레퍼런스

이 구역은 `reference-source/flowers.json`, `reference-source/brushes.json`, `reference-source/petals.json`, `reference-source/ink-paintings.json`에서 생성한다. 원문·외부 이미지는 링크로만 제공하며, 직접 관찰과 기관 설명, 구현 판단, 결과 검토를 구별한다.

현재 결과 링크는 프로젝트가 직접 제작한 로컬 crop이다. 새 수묵·담채 카드는 v14 개양귀비·코스모스·데이지의 스타일 분석 예시이며 원작 식물이나 구도의 복제가 아니다. I1·I2·I4는 시각적 채택, I3는 부분 채택, I5·I6는 별도 실행 시험·이력 감사 대상으로 구분한다. 사용자 취향은 확인 대기다. 기존 카드와 초기 검토 이력은 보존하며 외부 원본 이미지를 저장소에 복사하지 않는다.

### 관찰

- 사진 직접 관찰: 가운데 분홍 꽃은 넓은 설상화 약 8장이 방사상으로 둘러선다. 각 조각은 중심에서 좁게 출발해 바깥쪽으로 넓어지는 부채·주걱 모양이다.
- 사진 직접 관찰: 바깥끝은 둥근 타원이 아니라 얕게 갈라지고 물결치는 톱니 윤곽이다. 한 조각 안에서도 끝선의 높이가 다르다.
- 사진 직접 관찰: 위쪽 두 조각은 길고 비교적 곧게 펼쳐지며 아래쪽 조각은 말리거나 비스듬히 꺾여 짧게 보인다. 같은 길이의 회전 복제처럼 보이지 않는다.
- 사진 직접 관찰: 인접 설상화는 일부 가장자리에서 겹친다. 왼쪽과 아래쪽에는 좁은 틈도 있어 외곽이 완전한 원으로 닫히지 않는다.
- 사진 직접 관찰: 기부에서 끝으로 가는 길고 가는 밝은 결이 보인다. 접힌 능선은 밝은 분홍, 골과 겹침 부분은 진한 자주색으로 읽힌다.
- 사진 직접 관찰: 중심은 단색 노란 점이 아니라 작은 노랑·주황 돌기와 어두운 틈이 모인 원반이다. 사진에서 중심의 폭은 꽃 전체 폭보다 훨씬 작다.
- 사진 직접 관찰: 꽃 바로 아래로 가느다란 녹색 꽃자루가 이어지고, 아래 주변에 길고 뾰족한 녹색 조각들이 보인다. 앞면 꽃잎이 기부를 가려 총포의 전체 배열은 확인하기 어렵다.
- 기관 설명 근거: 바깥의 꽃잎처럼 보이는 부분은 설상화, 가운데는 관상화가 모인 두상화서다. 잎은 깊게 갈라진 실 같은 질감이므로 넓은 단엽을 붙이는 표현과 구별한다.

### 회피할 특징

- 매끈한 물방울형 타원 8개를 정확히 같은 길이·각도로 배치하기
- 설상화 끝을 모두 뾰족하게 만들거나 톱니를 크고 규칙적인 지그재그로 만들기
- 꽃 중심을 매끈한 검정 단추 또는 과도하게 큰 노란 구로 만들기
- 보이지 않는 꽃받침 구조를 확인한 사실처럼 기록하거나, 녹색 다섯 갈래 별을 종의 공통 구조로 단정하기
- 사진의 조명·채도·한 개체의 비대칭을 종 전체의 고정된 색과 치수로 취급하기

### 목표

- 넓은 분홍 설상화와 얕은 끝 톱니만으로 데이지의 길고 좁은 흰 설상화와 구분된다.
- 실루엣을 축소해도 몇 조각의 접힘, 길이 차이, 겹침 순서가 남는다.
- 작은 노란 관상화 군집과 가는 꽃자루 연결이 보인다.
- 사진급 복제보다 꽃의 배열·윤곽·곡률을 근거 있게 단순화한 그림을 목표로 한다.

### 구현

- 권장 구현: 기본 8장의 개별 베지어 경로를 만들고, 기부는 좁게·끝은 넓게 구성한다. 끝선에 3개 안팎의 얕은 굴곡을 넣는다. 이 수치는 해당 사진을 읽기 위한 디자인 선택이다.
- 권장 구현: 씨드로 각 조각의 길이·폭·기울기를 조금씩 달리하고, 일부 아래쪽 조각은 굽은 중심선과 짧은 투영 길이를 사용한다.
- 권장 구현: 뒤쪽 조각부터 그리고 겹침 경계에 낮은 불투명도의 자주색 음영을 둔다. 전체 꽃을 두른 진한 외곽선은 줄인다.
- 권장 구현: 밝은 능선 2~3개와 옅은 방사형 결을 조각별 곡률에 따라 휘게 그린다. 결은 텍스처 장식보다 접힌 방향을 설명하도록 사용한다.
- 권장 구현: 중심을 작은 황색·주황 점군과 일부 갈색 틈으로 구성하고 꽃 아래의 가는 꽃자루가 기부에 닿도록 연결한다.

### 미달·확인하지 못한 부분

- 직접 본 코스모스 사진은 앞면 위주 한 장이다. 총포 뒷면의 겹수·개수·꽃자루와 만나는 단면은 시각 확인하지 못했다.
- 기관 페이지의 품종별 사진 전체를 관찰한 것은 아니다. 겹꽃·통 모양 설상화 품종까지 이번 형태로 일반화하지 않는다.
- 사진은 절대 치수나 정량 색상 측정용 자료가 아니다. 구현의 비율·색은 사진 관찰을 바탕으로 한 도식화 선택이다.
- v11 결과의 채택은 실제 꽃 사진 동일성이나 사용자 미적 승인을 뜻하지 않는다. 꽃잎 재료의 세부 충실도 P3는 수채 때문에 부분 충족이며 약 11px의 작은 꽃은 별도 한계로 남긴다.

### 목표

- 여러 장의 길고 좁은 흰 설상화와 넓은 노란 관상화 원반으로 코스모스와 구분된다.
- 조각별 미세한 처짐·비틀림·길이 차이가 종이처럼 얇은 표면을 보여 준다.
- 중심과 설상화 경계의 깊이, 겹친 조각의 회색 그림자가 축소 화면에서도 읽힌다.
- 총포와 꽃자루는 기관 설명에 근거해 절제해서 보완하고, 관찰하지 못한 뒷면은 별도로 표시한다.

### 구현

- 권장 구현: 24~30개의 개별 설상화를 기본 디자인 범위로 사용한다. 이는 기관의 15~35개 범위 안에서 정한 표현 선택이며 고정된 종 진단 수치가 아니다.
- 권장 구현: 좁은 기부와 둥근 끝을 연결하는 긴 베지어 윤곽에 작은 끝 갈라짐을 넣고, 일부 조각의 한쪽 가장자리를 안으로 말아 폭 차이를 준다.
- 권장 구현: 설상화의 순서를 나누어 겹쳐 그리고 회청색의 옅은 골·가장자리 그림자를 추가한다. 모든 조각에 같은 줄무늬를 찍지 않는다.
- 권장 구현: 노란 원반을 낮은 볼륨으로 두고 중심의 작은 점군, 바깥의 더 큰 관상화 입자, 가장자리의 짧은 그림자를 단계적으로 그린다.
- 권장 구현: 꽃자루는 꽃 중앙 아래 총포까지 연결한다. 녹색 총포는 정면에서 필요한 만큼만 노출하고 자갈색 가장자리는 작은 색 차이로 표현한다.

- 사진 직접 관찰: Alvesgaspar 몽타주의 봉오리는 녹색 달걀형이며 줄기 끝이 고리처럼 굽어 아래를 향한다. 봉오리와 꽃줄기 표면에는 가는 털이 바깥으로 돌출한다.
- 사진 직접 관찰: 같은 몽타주의 개화 단계는 꽃잎 기부가 줄기 끝의 중심 아래로 모인다. 개화한 꽃 둘레에 큰 녹색 별형 꽃받침은 보이지 않는다. 이 사진만으로 꽃받침의 탈락 시점이나 개수를 판정하지 않는다.
- 기관 설명 근거: 꽃은 긴 꽃자루 끝에 단독으로 달리고 줄기는 거친 털을 지닌다. VicFlora는 가는 자주색 수술대, 푸른빛 꽃밥, 대체로 평평한 암술머리 원반을 기재해 사진의 어두운 중심 구조 해석을 뒷받침한다.

### 목표

- 큰 네 장의 얇은 붉은 꽃잎, 비대칭 컵 실루엣, 어두운 수술 고리로 다른 두 종과 구분된다.

- 봉오리를 표시한다면 아래로 굽은 꽃줄기와 털 있는 녹색 외피를 개화 형태와 구별한다.

### 구현

- 권장 구현: 뒤의 두 꽃잎과 앞의 두 꽃잎에 서로 다른 베지어 경로를 사용한다. 폭·높이·접힘·가림을 달리해 네 조각이 보이되 균등한 클로버 실루엣은 피한다.
- 권장 구현: 중심에서 가장자리로 휘는 몇 개의 주름과 투명도가 낮은 붉은 음영을 추가한다. 상단 테두리는 밝게, 겹친 안쪽과 컵 바닥은 짙게 하여 얇음과 깊이를 함께 표현한다.
- 권장 구현: 기부 반점은 꽃잎 좌표에 붙이고 겹침으로 일부 가린다. 별도의 검은 원 네 개를 중심 주변에 떠 있게 두지 않는다.
- 권장 구현: 중앙에 작은 회녹색·자주색 원반과 방사선, 그 밖에 짧은 선과 어두운 꽃밥 점군으로 수술 고리를 그린다.
- 권장 구현: 꽃자루는 컵 아래 중앙에 연결하고 일부 짧은 털을 넣는다. 봉오리에는 아래로 굽은 끝줄기와 달걀형 녹색 윤곽을 사용한다.

- 회화 직접 관찰: Redouté의 꽃잎은 가는 기부에서 올라와 뒤로 굽고, 붉은 끝의 물결과 노란 안쪽 면이 서로 다른 방향을 보여 준다. 굽은 가장자리만 복잡하고 모든 내부가 같은 굵기의 선으로 채워지지는 않는다.

- 밝은 면과 가장자리 일부의 여백이 남고, 어두운 겹침은 꽃잎 기부·접힌 한쪽·가려진 경계에 집중된다.
- 겹칠은 기존의 종별 꽃잎 윤곽 안에서 일어나며 사진 같은 질감보다 손으로 칠한 면의 차이를 목표로 한다.

### 구현

- 구현 제안: 꽃잎 기부→끝의 국소 곡선을 붓결의 주축으로 삼고 곡선의 접선에 맞춰 결 방향을 갱신한다. 기울어진 꽃잎에도 화면 기준의 직선 해칭을 적용하지 않는다.
- 구현 제안: 옅은 기본 면 위에 좁은 반투명 색띠를 소수만 겹친다. 접힘 한쪽에 색을 더하고 반대쪽에 밝은 가는 틈을 남겨, 전체 불투명도 저하만으로 수채를 표현하지 않는다.
- 구현 제안: 결의 폭과 농도를 기부·중간·끝에서 달리하고 끝에서는 줄인다. 이 변화는 붓의 눌림과 들어 올림을 연상시키는 설계이며 원작의 실제 필압 측정값이 아니다.
- 구현 제안: 외곽선은 가려진 짧은 구간이나 접힌 한쪽에만 허용한다. 종별로 정한 넓은 코스모스, 좁은 데이지, 큰 주름의 양귀비 윤곽은 유지한다.
