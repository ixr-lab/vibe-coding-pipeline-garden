# 수묵·담채 실제 작업 로그

날짜와 시간은 UTC다. 실행 전에는 가설로, 실행 후에는 관찰로 적는다. 이 문서는 사용자의 직접 승인을 대신하지 않는다.

## 03:46 — 새 의도와 기준

의도: 꽃잎 색을 바꾸고 꽃머리 위주의 비율을 개선하여 수묵·담채의 전체 식물과 여백을 만든다. [계획](plan.md)의 I1~I6를 고정했다. 이전 v11의 꽃잎 시험과 시각 판정은 보존하지만 새 목표의 판정 근거로 대체하지 않는다.

레퍼런스: 공식 소장처의 실제 작품 이미지와 카탈로그를 검토 중이다. 식물 모델·색 어댑터 구현 담당은 레퍼런스 페이지의 선행 갱신까지 코드 수정을 보류했다. 이미지와 작품 정보의 연결 오류 가능성도 발견하여 원본을 다시 확인한다.

이미 완료된 배포 사실: 새 요청 직전에 v11 검증 커밋 `cd38356430bcffd8ae80212641b31bf7ad594a20`을 public으로 전환했다. 원격 주요 파일 29개·v0~v11 태그 12개와 비인증 README/코드/PNG 3개를 바이트 대조했다. [당시 원격 증거](../../evidence/petals/publication-remote.json). 새 요청에 따라 가시성을 되돌리거나 다시 변경하지 않고 새 목표를 구현한다.

## 03:48 — 레퍼런스 선행 갱신 확인

공식 작품 3개와 기존 11개를 분리해 보드를 생성했다. 이미지 연결의 의문은 같은 두루마리의 서로 다른 세부 구간임을 공식 페이지/API로 확인했다. 전체 두루마리를 직접 보았다고 쓰지 않았다. 실제 Chrome에서 14카드·새 카드 3개·아직 결과 없음 표시를 확인하고 [화면](../../evidence/ink/reference-before-implementation.png)과 [JSON](../../evidence/ink/reference-before-implementation.json)을 저장했다. 이 시점까지 제품 구현은 시작하지 않았다. 선행 문서 커밋은 `b2db131`이다.

## 03:52 — v12 최소 통합 실행

의도 → 가설: 꽃을 줄이는 대신 연속 곡선·중하부 잎군·꽃목 접합으로 몸체를 만들면 전체 식물이 읽힐 것이다. 녹색 지형과 해·종이 점무늬를 제거하고 빈 종이를 남긴다. 담채와 무채색 먹, 색 선택·종별 기본색 복원을 연결한다.

변경: 새 엔진 API를 추가하고 기존 모델은 보존했다. 주줄기 3곡선, 짧은 곁줄기, 봉오리, 종별 잎 렌더를 만든다. 다섯 포기를 높낮이 있는 세 무리로 배치한다. 색 변환은 원래 기하·seed·알파를 유지하며 Canvas 스타일 경계에서 처리한다.

실제 실행: 동일 seed `271828`, `1440×1000`, DPR1, frame360. [전체](../../evidence/ink/v12-garden.png), [3종 한 포기](../../evidence/ink/v12-plants.png), [5브러시](../../evidence/ink/v12-brushes.png), [모바일](../../evidence/ink/v12-mobile.png), [실행 JSON](../../evidence/ink/v12-capture.json). 색/모드 3화면 구별·모바일 가로 넘침 없음·JS 오류 없음 3개 검사를 통과했다.

관찰 → 부분 채택: 꽃 아래에 실제 몸체와 긴 곡선이 생기고 배경 여백이 읽힌다. 그러나 코스모스 잎이 대나무 같은 삼각 부채꼴로 반복되고 중부의 반투명 잎 겹침이 회색 덩어리를 만든다. 다섯 포기의 축도 아직 수직 나열처럼 보인다. 이를 완료로 판정하지 않는다. 다음 가설은 잎군의 수·방향·종별 절개를 다르게 하고, 주역 위치와 낮은 응답 포기의 간격을 바꾸면 개별 식물과 빈 면이 더 선명해진다는 것이다. 독립 리뷰도 요청했다.

## 03:55 — 독립 검토와 시험 도구 점검

독립 리뷰도 중앙 회색 조각의 겹침, 세 종에 공통인 3갈래 잎군, 모바일에서 거의 닿는 상단 꽃을 지적했다. v13에서는 내부 빈 면과 종별 잎 구조, v14에서는 먹면·브러시 차이를 우선 확인한다. v12 기능 127개와 접근 입력 17개는 실제 Chrome에서 통과했다. 기능 통과와 새 미적 기준의 충족은 구분한다.

추가 관찰실 도구에서 단독 식물의 모델 seed는 지정했지만 재료 state.seed를 빠뜨린 것을 코드 검토로 발견했다. 제품 정원과 전체 화면의 seed는 올바르다. 최초 v12 단독 표본은 보존하고, 도구를 수정해 v12 태그 소스로 `v12-r2` 표본을 다시 실행한다. v13 이후 단독 비교에는 모델·재료 seed 모두 `271828`을 명시한다. 첫 v12 단독 표본을 동일 재료 조건의 전후 비교로 제시하지 않는다.

## 03:56 — v13 첫 개선 실행

의도 → 가설: 같은 3갈래 잎군을 줄이고 잎의 구조·크기·각도를 달리하면 겹침이 줄고 몸체 안의 종이가 보일 것이다.

변경: 기본 중앙 잎군 7→5(약 29% 감소), 1/2/3개의 불균등 잎군과 마디 간격, 코스모스 가는 분할 잎·데이지 긴 잎·개양귀비 넓은 갈래 잎을 구분했다. 꽃 없는 곁줄기 끝에는 작은 잎을 두었다. 주역 줄기는 S흐름을 주고 초기 포기 위치·높낮이를 조정했다. 먹 모드에서는 선택색만 바꿔도 전체 스프라이트를 재생성하지 않도록 했다.

실제 실행: [전체](../../evidence/ink/v13-garden.png), [3종 한 포기](../../evidence/ink/v13-plants.png), [모바일](../../evidence/ink/v13-mobile.png), [JSON](../../evidence/ink/v13-capture.json). 같은 조건 3개 검사 통과, 모델 포함 Node 22개 통과. 보존한 v12 태그를 새 도구로 재실행한 [v12-r2 JSON](../../evidence/ink/v12-r2-capture.json)의 전체 정원 해시 3개는 첫 v12와 모두 일치한다.

관찰 → 구조 채택·재료 보류: 중앙의 회색 조각이 줄고 각 줄기와 내부 빈 면이 읽힌다. 모바일 상단 두 꽃도 떨어졌다. 반면 코스모스 분할 잎은 가는 철사처럼 옅으며, 데이지·개양귀비의 같은 그라데이션 면은 아직 유리 조각 느낌이 있다. v14에서는 구조를 유지하면서 한 번의 먹면, 짙고 옅은 잎의 차이, 마른 붓 빈틈과 최소 구조선을 조정한다. 코스모스도 큰 삼각 잎으로 되돌리지 않고 가는 붓잎의 농담을 만든다.

## 04:00~04:02 — v14 두 번째 개선 실행과 판정

의도 → 가설: 주된 먹면 하나와 소수의 짙은 하부 잎군, 얇은 구조선을 구분하면 유리 같은 겹침과 연결이 사라지는 문제를 줄일 것이다.

변경: 넓은 잎의 균일 그라데이션·반복 고임을 제거했다. 아래 두 잎군을 진하게, 뒤·위·추가 밀도 잎군은 옅게 두었다. 코스모스 아래쪽은 짧은 압력 소엽과 가는 분지를 섞었다. 펜·먹·연필·드라이·수채가 잎에서도 다른 결을 내도록 했고 연필/수채에 최소 구조선을 더했다. 줄기·잎·봉오리는 중성 회색으로 통일했다.

코드 검토에서 별도 기능 결함도 확인했다. v13 age2.125의 잎 하나가 완성 위치에 먼저 나타나 자라는 잎자루에서 약 29.2px 떨어졌다. 잎자루가 완성된 후 잎이 드러나도록 실사용 성장 함수를 수정했다. [계산 증거](../../evidence/ink/growth-connection.json)는 1001곡선점 계산이며 래스터 측정으로 소개하지 않는다. 성숙 기하를 바꾸지 않았다.

실제 실행: [전체](../../evidence/ink/v14-garden.png), [3종 한 포기](../../evidence/ink/v14-plants.png), [5브러시](../../evidence/ink/v14-brushes.png), [색 선택](../../evidence/ink/color-modes.png), [모바일](../../evidence/ink/v14-mobile.png), [JSON](../../evidence/ink/v14-capture.json). 같은 조건 3개 검사와 Node 23개가 통과했다.

관찰 → 채택/부분 채택: 제작자와 [독립 시각 리뷰](visual-review.md)는 I1/I2/I4를 채택했다. 연필 연결과 아래 먹잎군도 개선됐다. I3은 부분 채택이다. 넓은 잎은 평평한 디지털 면에 가깝고 실제 먹의 국소 번짐·우연한 농도는 제한적이다. 참조작을 완전히 재현했다고 표현하지 않는다. 기본 코스모스와 현재 구도는 유지한다. 사용자 직접 미적 승인은 확인 대기다. 기능·접근 입력·성능·출처·이력 검증을 이어간다.

## 04:09 — 전체 페이지 검사에서 찾은 입력 영역 수정

재실행은 [132/132 통과](../../evidence/ink/final-r2-site-checks.json)했다. 실제 최종 UI [데스크톱](../../evidence/ink/delivery-desktop.png)·[모바일](../../evidence/ink/delivery-mobile.png)을 추가했다. 이 입력 영역 보정은 v14 기하·재료 태그 이후의 최종 통합 변경이다.

## 04:11~04:13 — 공개 전 경로 메타데이터 정리

[전체 이력 감사의 첫 결과](../../evidence/ink/privacy-audit-before.json)는 개인 경로 패턴 453건을 찾았다. 새 시험 JSON의 runtime와 로컬 링크 배열에 실행 폴더가 기록된 것이 원인이었다. 이 새 커밋들은 아직 원격에 push하지 않았다.

로컬 경로만 상대 표기로 바꾸고 아직 공개하지 않은 네 커밋 범위의 해당 JSON 메타데이터를 정리했다. 검사 결과·실행 시각·PNG·제품 코드·작성/커밋 시각·메시지는 유지했다. 공개된 v0~v11과 경계 커밋 `cd383564`는 바꾸지 않았다. [정리 영수증](../../evidence/ink/privacy-redaction.json)은 원 SHA와 공개용 SHA를 대응시킨다. v12 `d63b83b`는 동일하고 v13은 `6dfb850`, v14는 `ff638fa`가 됐다. 원본 실행의 JSON에 이전 SHA가 남아 있으면 이 대응표로 같은 제품 코드임을 확인한다. 이후 시험 도구도 공개 결과에 절대 경로를 기록하지 않도록 수정한다. 전체 selected-ref 감사를 다시 수행한 뒤에만 새 이력을 push한다.

## 04:15~04:18 — 감사 통과와 원격 재조회

재감사 findings0/errors0, 선택 refs·작업본 안정성을 확인했다. 최종 통합 문서 커밋 `89172d8`도 별도로 commit20개·blob539개·작업 후보508개를 감사해 findings0/errors0을 확인했다. main과 v12/v13/v14만 명시해 실제 push했다. 첫 원격 파일 대조는 GitHub TCP 읽기 시간 초과로 중단됐다. push나 가시성 변경을 반복하지 않고 읽기만 재시도했다. [완료한 원격 증거](../../evidence/ink/remote.json)는 정확한 커밋·파일29개·태그15개·비인증 파일3개의 바이트 일치를 확인한다. 공개 호스팅과 새 인증 권한 요청은 하지 않았다.
